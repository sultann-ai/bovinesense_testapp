Project: Bovine Sense Initial Testing App (Document Version: 1.0.0, Date: September 6, 2026).  1. Introduction & ScopeThe application is a React Native mobile app specifically designed to facilitate the field-testing phase for BovineSense's proprietary smart collars and eartags.  It serves as the primary interface for internal stakeholders (hardware engineers, software developers, and field testers) to validate sensor accuracy and verify Bluetooth Low Energy (BLE) transmission reliability.  Its scope focuses on diagnostic utility, streaming real-time telemetry (temperature and accelerometer data), and local data logging for offline analysis rather than end-consumer features.  2. Technical Stack & BrandingComponentTechnology & GuidelinesFramework & CI/CDReact Native with Expo for rapid development, and Expo Application Services (EAS) for cloud builds and OTA updates.  AuthenticationClerk is used for out-of-the-box user management to restrict access to authorized internal testers.  Analytics & Code ReviewPostHog tracks app stability and usage, while CodeRabbit provides AI-driven automated code reviews.  Styling & ColorsNativeWind is utilized with a palette of Dark Charcoal Grey (#4F5051) for headers, Light Blue (#7DBCE2) for accents/buttons, and White/Light Grey backgrounds.  TypographyUses System Sans-Serif for primary navigation and a Monospace font for easily scanning raw telemetry data and MAC addresses.  3. Functional RequirementsAuthentication (FR-01): The app must restrict unauthorized access, requiring testers to authenticate via Clerk using an email/password or magic links.  BLE Device Management (FR-02): The system shall scan for specific BovineSense UUIDs, display a device list (with MAC address, Device Name, and RSSI), and support automatic background reconnections.  Real-Time Data Display (FR-03): Upon connection, the UI will display ambient/skin temperature updates, visual 3-axis accelerometer data (X, Y, Z), and a raw hex/byte view for debugging.  Data Logging & Export (FR-04): Users can toggle recording sessions to store BLE packets locally with timestamps, which can later be exported as CSV or JSON files via the device's native sharing menu.  4. Non-Functional RequirementsPerformance: The application must asynchronously process high-frequency BLE notifications (up to 50Hz for accelerometer data) to ensure the UI remains responsive.  Reliability: Built to handle malformed data payloads without crashing, utilizing PostHog to log all unhandled exceptions and BLE connection timeouts.  Maintainability: Requires strict TypeScript typing to explicitly define BLE payload structures, ensuring a unified contract between hardware and front-end teams.
